## 2. Current Progress & Completed Milestones (v2.0.0 Architecture)

As of the current session, the repository has been upgraded from legacy v0.4.4 to **v2.0.0**, achieving full technical and cryptographic parity with GUI v2:

### A. Cryptographic Pipeline Modernization
* **NIST FIPS 203 ML-KEM Standard:** Replaced deprecated `pqcrypto-kyber` with official **NIST FIPS 203 ML-KEM-768/1024** (`fips203` crate).
* **Dual-Profile Hybrid KEM:**
  * **Profile 1: X-Wing (Default):** ML-KEM-768 + RFC 7748 X25519 (`x25519-dalek`) using official IETF draft domain separator `\.//^\` (`XWING_LABEL`), SHAKE256 seed expansion (`expand_xwing_seed`), and SHA3-256 combiner digests (`compute_hybrid_combiner`).
  * **Profile 2: Cypherpunk:** ML-KEM-1024 + X25519 using `CYPHERPUNK_LABEL` (`OMBMX2`).
* **Hardened Argon2id KDF:** Configured with 64&nbsp;MiB RAM (`ARGON2_M_COST = 65_536`), 3 passes (`ARGON2_T_COST = 3`), and 4 parallel lanes (`ARGON2_P_COST = 4`).
* **Zero-Plaintext In-Memory Streaming:** Encrypts directory trees and single files on-the-fly through bounded in-memory buffers (1&nbsp;MiB ceiling) directly into authenticated AEAD ciphertext. **Zero unencrypted intermediate `.tar` archives are ever staged on disk.**
* **Memory Scrubbing:** Sensitive plaintexts, symmetric master keys, and private KEM seeds are held within `zeroize::Zeroizing` wrappers and wiped immediately after cryptographic operations.

### B. Defensive Filesystem & Anti-Coercion Layer (`fs_guard` & `deception`)
* **Collision-Proof Atomic Publication:** Direct OS bindings (`libc` for Unix, `windows-sys` for Windows) via `atomic_publish_noreplace` and `atomic_publish_dir_noreplace` prevent overwriting existing files or directories.
* **Pre-Flight Telemetry:** Storage capacity estimation and path collision detection implemented via `fs2` and canonical path validation (`assess_storage_and_paths`).
* **Archive Hardening:** Defensive TAR extractor enforcing strict zip-slip path sanitization, anti-symlink traversal checks, file type allowlists, and directory depth limits.
* **Interactive Duress Response:** Entering a secondary deception passcode during decryption triggers an in-place CSPRNG overwrite against the target `.obk` key file on disk (enforcing `st_nlink > 1` protection) and returns a generic authentication error.

### C. Zero-Tauri Headless Core Decoupling
* Completely decoupled `stream.rs` and `pipeline.rs` from `tauri::{AppHandle, Emitter}`.
* Replaced desktop GUI event emitters with generic, zero-allocation callback hooks (`Option<&dyn Fn(u8)>`). Unit tests and headless scripts run cleanly with `None`, while the CLI hooks into `indicatif`.

### D. CLI Subcommand Surface & Terminal UX (`src/main.rs`)
Implemented 5 core subcommands:
1. `encrypt`: Locks directory/file into `.obv` vault. Supports generating fresh keypairs or sealing against existing `.obp` Public Keys (`-p / --public-key`).
2. `decrypt`: Authenticates and extracts `.obv` vaults using `.obk` Private Keys.
3. `keygen`: Generates standalone reusable `.obp` Public + `.obk` Private keypairs.
4. `inspect`: Evaluates disk space requirements and path conflicts (supports human-readable and `--json` outputs).
5. `clean`: Multi-target scanner (`-d / --target-dir` with `ArgAction::Append`) supporting path deduplication and file-to-parent normalization to purge `.ombracrypt_stage_*` remnants.
* **Cooperative Signal Cancellation:** Intercepts `SIGINT` (Ctrl+C), `SIGTERM`, and `SIGHUP` on Unix and Console Control Events on Windows via `ctrlc` (`termination` feature). Handler registration propagates errors (`map_err(...)`) and executes a strictly non-blocking atomic store (`AtomicBool::store(true, Ordering::Relaxed)`). An explicit pre-commit cancellation barrier in both encryption and decryption ensures staged files and directories are cleanly rolled back before atomic publication.
* **Strict Credential Zeroization & Safe Process Unwinding:** Password ingestion (`fetch_credential`) wraps all passcodes and confirmation buffers directly in `zeroize::Zeroizing<String>` without intermediate allocations. Purged all `std::process::exit` calls across the codebase; `run()` returns `Result<(), String>` and `main()` returns `std::process::ExitCode` to guarantee deterministic stack unwinding and destructor zeroization.
* **Multi-Target Cleaner:** Multi-target scanner (`-d / --target-dir` with `ArgAction::Append`) supporting path deduplication and file-to-parent canonicalization to purge orphaned `.ombracrypt_stage_*` remnants without clobbering active transfers.
* **Terminal UI:** Ombracrypt branding banners and animated `indicatif` progress bars (with `-q / --quiet` option for script suppression).

## 3. Architectural Decisions (Locked In)

| Decision | Rationale & Specification |
| :--- | :--- |
| **Wire Format Parity** | Must strictly follow GUI v2 container format (`OMBV\x02` for vaults, `OBSK\x02` for private keys, `OBPK\x02` for public keys). Any deviation breaks cross-platform interoperability. |
| **Default Algorithms** | Symmetric cipher: `xchacha20` (XChaCha20-Poly1305). KEM profile: `xwing` (NIST FIPS 203 ML-KEM-768 + X25519). Secondary options `aes256gcm` and `cypherpunk` are supported. |
| **Smart Output Pathing** | When `--output-dir` is not explicitly provided, outputs default to the parent directory of the target (or `.` if relative), avoiding polluting current working directory unless intended. |
| **Atomic Publication** | Never silently overwrite destination files or folders. Always fail-closed on collision to prevent accidental user data loss. |
| **Zero Plaintext Staging** | Plaintext archives must never be written to temporary disk files prior to encryption. Streaming through bounded memory buffers is mandatory. |
| **Binary Invocation** | Primary binary name is `ombracrypt` (`[[bin]] name = "ombracrypt"`). |
| **Licensing** | **CAL-1.0** (Cryptographic Autonomy License 1.0) across both GUI and CLI repositories. |
